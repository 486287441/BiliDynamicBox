BiliDynamicBox

在 B 站动态页把信息流变成「收件箱」：只展示视频动态，按今天 / 昨天 / 日期分组；点「想看」进稍后再看，点「不想看」进垃圾箱，刷新后不再打扰你。

范围 仅 t.bilibili.com 栈 Vue 3 · Pinia · MV3 数据 本地存储，不上传
安装说明 打开动态页

00 · 界面

收件箱式动态流

替换原动态内容区，卡片网格 + 日期分组，参考 BewlyBewly 的扫读体验。

01 · 能力

为「快速决策」设计的功能

  1. 日期分组今天 · 昨天 · 更早

    打开动态页即可按时间轴扫读更新，不必在原生时间线里上下翻找。

  2. 想看稍后再看

    一键加入 B 站稍后再看，使用浏览器已有登录 Cookie，无需配置 API Key。

  3. 不想看本地垃圾箱

    卡片移入垃圾箱并持久化；刷新后该条动态不再出现，可从顶部工具栏恢复。

  4. 取关确认连续 5 次阈值

    同一 UP 主连续五次「不想看」时弹窗询问是否取关，避免误伤也帮你清理低兴趣源。

  5. 仅视频动态过滤图文

    图片动态与纯文字动态不进入卡片流，专注视频观看决策。

02 · 原则

产品与技术边界

  1. 1
    只改动态页仅在 https://t.bilibili.com/ 替换内容区，不碰首页、搜索与其它路由。
  2. 2
    本地优先不想看记录与垃圾箱存在 chrome.storage.local，不上传服务器。
  3. 3
    轻反馈想看后 toast 提示即可，不打断连续浏览节奏。
  4. 4
    单条隐藏不想看只隐藏当前动态，不连带屏蔽该 UP 的其它内容。
  5. 5
    开源可审Manifest V3 + Vue 3 源码在 GitHub，可自行构建与审查请求行为。

03 · 安装

开发者模式加载

当前为早期版本，需本地构建后加载未打包扩展。

克隆仓库 → 在 extension/ 执行 npm ci && npm run build → Chrome / Edge 扩展程序页选择「加载已解压的扩展程序」，指向 extension 目录。登录 B 站后访问动态页即可。

# 克隆与构建
git clone https://github.com/486287441/BiliDynamicBox.git
cd BiliDynamicBox/extension
npm ci
npm run build

# 然后在浏览器加载 extension/ 目录（含 dist/）

04 · 问答

常见问题

需要 B 站 API Key 吗？
不需要。扩展通过页面同源请求调用公开接口，鉴权依赖你已在浏览器中登录的 Cookie（credentials: "include"）。
为什么只看到视频？
产品范围刻意限定为视频动态，图片与纯文字动态在数据层被过滤，减少噪音。
「不想看」能恢复吗？
可以。条目进入垃圾箱，可从顶部工具栏打开垃圾箱弹窗恢复。
隐私数据如何处理？
不收集个人信息；不想看与垃圾箱仅本地存储。详见仓库内 privacy-policy.md。
UI 风格从哪来？
交互与视觉参考 BewlyBewly 的卡片扫读体验，实现为本仓库独立代码。
