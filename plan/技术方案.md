# B站动态收件箱插件 — 技术方案

基于 `需求.md` 的已定 PRD，本文只定义实现路线，不改动产品决策。

---

## 1. 技术选型结论（对齐 Bewly 栈）

### 1.1 总体方案

- **Chrome/Edge 扩展（Manifest V3）+ Content Script 注入页面**
- **前端渲染：Vue 3 + TypeScript + Pinia（与 Bewly 主工程一致）**
- **构建：Vite + tsup（沿用 Bewly 的双构建思路）**
- **扩展兼容层：`webextension-polyfill`（对齐 Bewly）**
- **存储：`chrome.storage.local`（必要时回退 `localStorage` 仅缓存 UI）**

### 1.2 选型理由（对应 PRD）

1. PRD 要求仅在 `https://t.bilibili.com/` 生效，且替换内容区；Content Script 能精准挂载、最小化影响站点其它页面。  
2. 你明确要求“按 Bewly 栈改 plan”，因此 UI、状态与工程组织直接对齐 `Vue + Pinia + Vite + tsup`，后续复用 Bewly 的工程经验更顺手。  
3. PRD 要求“不想看记录与 UP 计数持久化”；`chrome.storage.local` 对扩展场景更稳定，也便于未来导出。  
4. PRD 要求“只呈现视频动态”；在数据适配层统一过滤类型，Vue 渲染层只接收视频卡片数据，规则最清晰。

## 2. 项目结构

```text
extension/
  manifest.json
  src/
    contentScripts/
      dynamic-inbox.ts        # Content Script 入口：挂载 Vue 应用
      host-detect.ts          # 仅在 t.bilibili.com 生效 + 页面就绪检测
      page-replace.ts         # 替换内容区并挂载 #bewly-inbox-root
    app/
      App.vue                 # 收件箱根组件
      main.ts                 # createApp + pinia 挂载
      router-bridge.ts        # SPA 路由变化监听与重挂载协调
    store/
      inbox.ts                # 分组数据、加载态、错误态
      decision.ts             # 想看/不想看、UP计数、阈值触发
      trash.ts                # 垃圾箱状态与恢复
    domain/
      types.ts                # DynamicItem/CardModel/Decision enums
      filter-video.ts         # 动态过滤：仅保留视频动态
      group-by-date.ts        # 今天/昨天/日期 分组
      decision-rules.ts       # 连续5次阈值规则
    services/
      bilibili-api.ts         # 读取动态数据、稍后再看、取关请求封装
      storage.ts              # dislike 集合、up 计数、垃圾箱数据持久化
      toast.ts                # 轻提示反馈（可接 vue-toastification）
    components/
      InboxGroup.vue
      VideoCard.vue
      TopToolbar.vue
      TrashModal.vue
    styles/
      base.scss
      cards.scss
      toolbar.scss
      trash.scss
  package.json
  vite.config.ts
  vite.config.content.ts
  tsup.config.ts
```

## 3. 运行与部署

### 3.1 本地开发

1. `pnpm install`
2. `pnpm dev`（Vite + 内容脚本构建联动 watch 到 `dist`）
3. 浏览器扩展管理页加载 `dist`（开发者模式）
4. 打开 `https://t.bilibili.com/` 验证页面注入

### 3.2 打包发布

1. `pnpm build` 产出 MV3 包
2. 本地打包 zip 后手动安装验证
3. 后续可上架 Chrome Web Store / Edge Add-ons（非本阶段必须）

## 4. 数据流设计

### 4.1 核心实体

- `VideoDynamicCard`
  - `dynamicId`
  - `videoBvid` / `videoAid`
  - `title`
  - `cover`
  - `upMid`
  - `upName`
  - `publishAt`

- `UserDecisionStore`
  - `dislikedDynamicIds: string[]`
  - `upDislikeCounter: Record<upMid, number>`
  - `trashItems: Record<dynamicId, VideoDynamicCard>`
  - `updatedAt`

### 4.2 处理流程（Pinia 驱动）

1. 拉取动态原始数据。  
2. `filter-video.ts` 过滤出视频动态（图片/文字动态直接丢弃）。  
3. `storage.ts` 读取本地 `dislikedDynamicIds`，剔除已“不想看”项。  
4. `group-by-date.ts` 按“今天/昨天/日期”分组。  
5. `inbox` store 推送数据到 Vue 组件树并渲染卡片。  
6. 用户点击：
   - **想看**：调用稍后再看接口 -> toast 成功/失败
   - **不想看**：写入垃圾箱 + 计数 + 从当前列表移除  
7. 若某 `upMid` 计数达到 5，弹确认框；确认后调用取关接口并反馈结果。

## 5. PRD 对应实现表

| PRD 决策 | 实现要点 |
| --- | --- |
| 仅动态页生效 | `host-detect.ts` 限定域名与路径，非目标页不初始化 |
| 只显示视频动态 | `filter-video.ts` 作为渲染前硬过滤 |
| 今天/昨天/日期分组 | `group-by-date.ts` 输出分组结构，`InboxGroup.vue` 渲染标题 |
| 卡片中常驻想看/不想看 | `VideoCard.vue` 固定按钮区，不走 hover 显示 |
| 不想看仅隐藏当前动态 | 仅记录 `dynamicId`，不扩大到同 UP 全部内容 |
| 垃圾箱入口在顶部工具栏 | `TopToolbar.vue` 固定入口，打开 `TrashModal.vue` |
| 想看后 toast 反馈 | `toast.ts` 统一提示，不改变主布局 |
| 连续5次不想看立即弹取关 | `decision-rules.ts` + `decision` store 触发 confirm 流程 |

## 6. 风险与约束

1. B站动态接口字段可能变动，`bilibili-api.ts` 需做字段兜底解析。  
2. 页面可能为 SPA 路由切换，需监听 URL 与容器重挂载，防止重复注入。  
3. 取关与稍后再看接口依赖登录态，需处理未登录或权限失败分支。  
4. 数据量较大时渲染性能要控：按分组增量渲染，避免一次性插入过多节点。

## 7. 编码参考约束（新增）

后续进入各模块写代码时，必须对照 `bewly-动态相关/文件清单.md`：

1. **先看清单再动手**：每个模块开工前先定位对应的 Bewly 参考文件，再写本项目代码。  
2. **优先复用已验证结构**：卡片结构、动态数据流、接口接线、样式层级优先参考清单中的核心链路文件。  
3. **允许按 PRD 裁剪，不允许偏离目标**：可删除与本项目无关能力（如非视频动态、额外 tab），但不得破坏“仅视频动态 + 想看/不想看 + 垃圾箱 + 5次触发取关”主链路。  
4. **实现后要做对照自检**：每完成一个模块，检查“本实现是否已参考清单中的对应文件”并记录差异点。
