01 · Executive Summary

执行摘要

BiliDynamicBox 在 https://t.bilibili.com/ 将原生动态内容区替换为视频收件箱：按今天、昨天与更早日期分组，用户以「想看 / 不想看」完成决策。数据仅存本地浏览器，不依赖自建后端。

核心 Takeaways

  • 产品目标：降低动态页噪音，把浏览转为可执行的观看清单与过滤规则。
  • 范围边界：仅视频动态；图文与纯文字不进入卡片流；仅动态页生效。
  • 技术路径：MV3 Content Script + Vue 3 + Pinia + chrome.storage.local。
本文档回答的问题
为什么要做收件箱？用户能做什么、不能做什么？工程上如何注入、过滤、持久化与调用 B 站接口？
02 · Background

背景与问题定义

B 站动态页聚合了关注 UP 的多种更新类型。对以视频消费为主的用户，混排时间线意味着更高的扫读成本与更慢的决策速度。

当前现状

原生动态流按时间混排视频、图片与文字。用户若只想处理「今晚要不要看」，需要在无关内容上反复滚动。稍后再看与屏蔽能力分散在单条操作菜单中，缺少「收件箱式」的批量处理心智。

核心问题

信息噪音高、决策成本高：用户希望在同一页面快速划分「想看」与「不想看」，并可持续地维护过滤结果。

产品首要目标（已定）：quick_filter —— 优先快速筛掉不感兴趣动态，而非推荐算法或社交运营能力。

衡量标准

维度 当前（原生） 目标（扩展） 差距
内容类型 视频 + 图文 + 文字混排 仅视频卡片 需过滤层
时间结构 连续时间线 今天 / 昨天 / 日期 需分组逻辑
负反馈 单条隐藏分散 垃圾箱 + 刷新不现 需本地持久化
03 · Product & Architecture

功能范围与技术架构

本章对齐已定 PRD 与 plan/技术方案.md：先列用户可见能力，再说明扩展如何挂载与持久化。

功能范围（已定）

  • 核心流程：在动态页对视频卡片执行「想看 / 不想看」。
  • 分组：today_yesterday_then_date —— 今天、昨天、更早按具体日期。
  • 不想看：hide_only_this_post，仅隐藏当前动态。
  • 垃圾箱：top_toolbar 入口；误操作可恢复。
  • 取关：同一 UP 连续 5 次不想看 → immediate_modal 确认。
  • 想看反馈：toast_only，不打断浏览。

技术选型

Chrome/Edge Manifest V3；Vue 3 + TypeScript + Pinia；Vite + tsup 双构建；webextension-polyfill；存储 chrome.storage.local。

extension/src/
  content/     → 注入、页面替换、挂载 #bewly-inbox-root
  domain/      → filter-video, group-by-date, decision-rules
  store/       → inbox, decision, trash
  services/    → bilibili-api, storage, toast
  components/  → VideoCard, InboxGroup, TopToolbar, TrashModal

数据流要点

发现 1：鉴权不引入密钥

扩展通过页面同源请求调用 B 站公开接口，credentials: "include" 使用浏览器已有登录 Cookie，仓库内不含 API Key。

发现 2：过滤在领域层完成

filter-video.ts 统一剔除非视频动态；Vue 层只渲染 VideoDynamicCard，避免 UI 与规则分叉。

UI 视觉参考 BewlyBewly 卡片扫读体验；实现为本仓库独立代码，上游工程需本地单独克隆对照。 — README，2026
04 · Conclusions

结论与建议

BiliDynamicBox 用最小页面侵入换取清晰的决策界面；成功取决于规则一致、本地可信与轻量反馈。

核心结论

  1. 产品价值在于把动态页从「信息流」改为「待办收件箱」，而非改造全站。
  2. 技术栈与 Bewly 对齐，利于复用工程经验；边界由 domain 层约束。
  3. 隐私模型简单：不收集个人信息，负反馈数据仅 chrome.storage.local。

明确不做

不改造首页 / 搜索；不含推荐算法、批量运营、社区协作；不要求键盘快捷键（当前以点击为主）。

下一步建议

贡献者可按 plan/M01–M05 模块推进；使用者 clone 后在 extension/ 执行 npm ci && npm run build，开发者模式加载 extension 目录。

Call to Action
登录 B 站 → 加载扩展 → 打开 t.bilibili.com → 用今天分组处理一轮更新，验证想看、不想看、垃圾箱与第 5 次取关弹窗。
