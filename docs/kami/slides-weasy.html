BiliDynamicBox

把 B 站动态页变成可处理的视频收件箱
产品介绍 · 2026.05
01 · 问题

原生动态页混排太多类型，决策成本高

视频、图片、文字挤在同一条时间线里，用户只想回答「今晚看不看」却要反复滚动。

用户痛点

信息噪音高；稍后再看与屏蔽入口分散；缺少按日处理的节奏。

产品定位

quick_filter：优先筛掉不感兴趣内容，而非改造推荐算法。

01
BiliDynamicBox
02 · 方案

仅在 t.bilibili.com 替换内容区为收件箱卡片流

A日期分组

今天 / 昨天 / 更早按具体日期，先处理最新。
B仅视频

图文与纯文字在数据层过滤，UI 只渲染视频卡片。
C想看

一键加入稍后再看，toast 反馈不打断浏览。
D不想看

进垃圾箱，刷新不再出现；顶部工具栏可恢复。
02
BiliDynamicBox
03 · 规则

同一 UP 连续 5 次不想看会立刻弹窗确认取关

不想看只隐藏当前条动态，不连带屏蔽该 UP 其它内容。第 5 次触发 immediate_modal，避免误伤也帮助清理低兴趣源。

体验原则：点击为主、轻反馈、垃圾箱入口固定在顶部工具栏。
03
BiliDynamicBox
04 · 技术

Manifest V3 + Vue 3 + Pinia，数据只存本地

注入 Content Script 替换内容区，挂载 #bewly-inbox-root host-detect + page-replace
构建 Vite + tsup 双构建至 extension/dist 对齐 Bewly 工程习惯
存储 chrome.storage.local 垃圾箱 · dislike · UP 计数
接口 同源 Cookie，无 API Key bilibili-api.ts

BiliDynamicBox

M01 项目骨架与页面接管 注入与 Vue 挂载

M03 卡片与想看 / 不想看 VideoCard 交互
M04–M05 垃圾箱持久化 · 取关阈值 TrashModal · decision-rules

06 · 隐私

不收集个人信息，负反馈数据不上传服务器

扩展不读取或记录 Cookie 内容；仅通过 credentials: include 调用公开接口。不想看与垃圾箱仅存 chrome.storage.local，卸载扩展即可清除。

详见仓库 privacy-policy.md。
